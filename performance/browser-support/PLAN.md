# Browser-compatible pristine support proof

Scope: isolated proof only; no production integration, remote write, external package, local browser, or real-browser claim.

1. Preserve the final Node benchmark result files and its compiled asset unchanged.
2. After the Node worker freezes shared files, extract crypto-free canonical table/recipe/topology encoding, binary decoding checks, semantic invariants, owned snapshots, and source-bound single-use token consumption. Public Node and browser validators compute their own actual hashes. Internal platform hash-driver plumbing is not a defense against hostile same-realm JavaScript.
3. Keep Node generation and synchronous crypto wrappers separate. Browser uses only native asynchronous Web Crypto. Copy caller bytes, decoded typed tables and manifest before the first await. Do not copy or enumerate terrain Cell objects.
4. Preserve exact original seeded chunk ordering, reciprocal geometric edges, root/object/material/connectivity validation and all cut/leave/split code.
5. Exercise bounded tests first, including pre-await mutation, subviews, corruption, and explicit topology capacity rejection. Build a Vite browser entry with a resolver guard against Node builtins. Neither Node Web Crypto tests nor a successful Vite build proves browser execution.
6. When the lead permits city workloads, run isolated serial process profiles for digest/decoding/full validation/hydration, accounting separately for the transient full topology byte buffer required by nonstreaming Web Crypto. Compare exact ordered 20-cut oracle hashes. Keep peak-vs-retained memory labels honest.

Frozen assets' recipe source checksums will no longer describe the edited shared source files. Do not rewrite historical Node results or silently bless the stale asset. Any new browser-generation artifact must live here with an updated recipe manifest.
